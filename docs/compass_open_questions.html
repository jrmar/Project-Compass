OQ-2 Risk Scoring Formula Needs Decision
Question
How are detection results and assessment answers combined into a single overall risk score for the dashboard? What are the weights for each component?
Recommended Formula
Overall Score = (Detection Score × 0.5) + (Assessment Score × 0.5)

Detection Score: High/Unknown tools × 15 pts, Medium × 7 pts, Low × 2 pts (capped 100)
Assessment Score: 100 minus percentage of Yes/Partial answers

With current data: Detection ~74, Assessment ~75 → Overall: HIGH (74.5)
Team Decision Needed
Agree with the 50/50 weighting? Should detections carry more weight than governance answers? Should the Unknown AI tool carry a higher penalty since it cannot be identified?
OQ-3 Gap Assessment Questions - Static or Dynamic? Needs Decision

Should the 16 governance questions be the same every time (static), or should a small number of additional questions appear based on what categories were detected in the scan?
Recommendation

OQ-4 PDF Export Method Needs Decision
Options
Browser Print (window.print()): Zero extra libraries, uses browser PDF engine, works well with print-optimized CSS. Output quality depends on browser settings.

jsPDF: Full programmatic control, consistent output, but significantly more build time and more things that can fail during a live demo.
Recommendation
Use browser print for MVP. A dedicated print CSS stylesheet (media print) that hides navigation, applies white backgrounds, and formats report content takes roughly half a day of work. jsPDF can be added post-capstone if a production version is pursued.
OQ-5 Application Structure - Multi-Page vs Single Page App Needs Decision
Options
Multi-Page HTML: Separate .html file per step. State passes via localStorage. Each step is independent - if one breaks, others still work. Simplest to build and debug.

Single Page App: One HTML file, JavaScript shows and hides views. Smoother step transitions, all data lives in memory, but one bug can break the entire flow.
Recommendation
Multi-page HTML with localStorage for state. For a capstone demo timeline, simpler and more demo-reliable is the right tradeoff. A shared step progress bar component makes it feel like one continuous app even across separate pages.
OQ-6 Login Screen vs. Direct to Upload Needs Decision
Options
No login: App starts directly at the upload screen. Fastest path to demo content, minimal friction.

Demo login screen: Pre-filled credentials (demo@compass.ai / Compass2026) and a single Sign In button that navigates to upload. Adds realism. Roughly 2 hours of build time.
Recommendation
Add a minimal login screen. It establishes the product as a real enterprise tool from the first moment, creates a natural demo start point, and takes only 2 hours to build. The login does not need real authentication - just navigate on button click.
OQ-7 Firewall Rule Format for Block Action Needs Decision
Options
Generic: Readable by everyone, vendor-neutral.
Palo Alto PAN-OS: Most widely deployed enterprise firewall, recognized by security professionals.
Cisco ASA: Common in mid-market enterprise environments.
Multi-format toggle: Show all three with a format selector in the modal.
Recommendation
Multi-format toggle: Generic, Palo Alto, and Cisco ASA. The toggle is a small UI component (3 to 4 hours). It shows technical depth to the security-focused audience while keeping a readable generic format for non-technical viewers. This is the same data rendered three ways.
OQ-8 SIEM Query Format for Monitor Action Needs Decision
Options
Splunk SPL: Largest installed SIEM base in enterprise. SPL queries are recognizable to most security professionals.
Microsoft Sentinel KQL: Fastest growing enterprise SIEM. KQL is familiar to Microsoft shop audiences.
Generic alert description: Non-technical explanation of what the alert does.
Recommendation
Show Splunk SPL and Microsoft Sentinel KQL with a platform toggle, plus a generic description tab. Query text is already drafted in the PRD. This covers the two most common enterprise SIEMs and ensures the demo resonates with any security audience.

16 governance questions mapped to the four NIST AI RMF functions: Govern, Map, Measure, and Manage. Each "No" or "Unsure" answer generates a finding with a risk level and recommended action. Answer options: Yes (100 pts) / Partial (50 pts) / No (0 pts) / Unsure (0 pts, flagged for follow-up).

ID Question NIST Ref Gap If "No"
G-01 Does your organization have a written AI usage policy that defines approved and prohibited uses? Govern 1.1 High
G-02 Is there a designated owner or team responsible for AI governance decisions? Govern 1.2 Medium
G-03 Are employees required to review and acknowledge AI usage policies? Govern 1.3 Medium
G-04 Does your organization review and update AI policies at least once per year? Govern 1.7 Low
Map AI Tool Inventory and Risk Awareness Does the org understand what AI is in use and what risks those tools carry?
ID Question NIST Ref Gap If "No"

M-04 Has a formal risk assessment been conducted for any AI tool currently in use? Map 5.1 Medium
