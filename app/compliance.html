NIST AI 100-1
NIST AI Risk Management Framework

The NIST AI RMF (January 2023) provides a voluntary, flexible framework for managing risks associated with AI systems throughout their lifecycle. It is organized into four core functions.

NIST AI 100-1 Published: January 2023 Voluntary Lifecycle-spanning
Function 1
GOVERN
Establishes the organizational culture, policies, and accountability structures needed for responsible AI risk management across the enterprise.
  • Define AI risk tolerance and appetite
  • Establish roles, responsibilities, accountability
  • Build AI risk governance policies
  • Train staff on AI risk concepts
Compass Support Org profile setup and role-based report views reflect GOVERN by capturing who uses AI and in what capacity, establishing accountability context for each assessment.
Function 2
MAP
Establishes the context in which AI systems operate and identifies the risks, impacts, and harms associated with each system and use case.
  • Categorize AI tools and use cases
  • Identify stakeholders and impacted groups
  • Document data sources and provenance
  • Assess organizational exposure
Compass Support The log-based AI tool discovery phase (Detect) directly fulfills MAP — surfacing what AI systems exist, their categories, vendors, and risk tiers.
Function 3
MEASURE
Analyzes and assesses identified AI risks, impacts, and uncertainties — including bias, explainability, robustness, and privacy concerns.
  • Evaluate risks against defined criteria
  • Test for bias and fairness
  • Assess explainability and transparency
  • Track residual risks over time
Compass Support The NIST control questionnaire (Assess phase) measures your organization's maturity across each RMF domain, producing a gap score that quantifies current vs. target posture.
Function 4
MANAGE
Prioritizes and addresses identified risks through treatment plans, monitoring protocols, incident response, and ongoing documentation.
  • Develop risk treatment plans
  • Implement monitoring and response
  • Document decisions and residual risks
  • Continuously improve controls
Compass Support Report phase delivers prioritized remediation recommendations. The inventory approval workflow (Approved / Review / Blocked) creates a traceable management decision log.
ℹ️
NIST released the AI RMF Playbook alongside AI 100-1, providing actionable guidance for each subcategory. A companion document, NIST AI 600-1 (Generative AI), was published in July 2024 and addresses specific risks from large language models. Check airc.nist.gov for the latest publications.
NIST SP 800-218A
Secure Software Development for AI

NIST SP 800-218A extends the Secure Software Development Framework (SSDF) to address unique challenges in AI and machine learning system development, including model training, data pipelines, and generative AI integrations.

NIST SP 800-218A Initial Draft: August 2024 Extends SSDF (SP 800-218)
PO
Prepare the Org
Define security requirements for AI systems before development begins. Establish roles, tools, and policies specific to AI/ML workflows.
Compass Relevance Org profile + role collection during login captures who is accountable for AI governance decisions.
PW
Produce Well-Secured Software
Design and implement AI systems with security controls, including data validation, model integrity checks, and output filtering.
Compass Relevance Detection phase flags tools with missing data controls; questionnaire covers model security practices.
PS
Protect the Software
Protect AI artifacts (models, datasets, pipelines) from unauthorized access, tampering, and supply chain compromise throughout their lifecycle.
Compass Relevance Supply chain risk is surfaced in inventory via third-party tool flagging and vendor risk tiers.
RV
Respond to Vulnerabilities
Identify, triage, and remediate vulnerabilities in AI systems, models, and dependencies — including those introduced post-deployment.
Compass Relevance Report remediation recommendations are severity-ordered to support triage and incident response planning.
OWASP LLM Top 10 · 2025
Top Security Risks for LLM Applications

The OWASP Top 10 for LLM Applications (2025, v2.0) identifies the most critical security vulnerabilities specific to systems built with large language models. The table below notes which risks Compass can surface through log analysis.

OWASP LLM Top 10 v2.0 — 2025 owasp.org/www-project-top-10-for-large-language-model-applications
ID Risk Detected by Compass
LLM01:2025
Prompt Injection
Adversarial inputs manipulate LLM behavior — including indirect injection via untrusted external content retrieved by the model.
 Partial
Log volume anomalies from LLM API calls can indicate injection campaigns; payload content is not inspected.
LLM02:2025
Sensitive Information Disclosure
LLM outputs inadvertently reveal PII, credentials, proprietary data, or confidential system information.
 Partial
Tools with a "Confidential" data classification flag are surfaced; content of API responses is not inspected.
LLM03:2025
Supply Chain
Vulnerabilities in third-party models, datasets, plugins, or pre-trained weights used within the AI stack.
 Yes
The AI Inventory enumerates third-party vendors and tools, giving visibility into supply chain dependencies.
LLM04:2025
Data and Model Poisoning
Training data or fine-tuning datasets are corrupted to introduce backdoors, biases, or malicious behavior into the model.
 Not Detected
Requires inspection of training pipelines — outside the scope of network log analysis.
LLM05:2025
Improper Output Handling
Downstream systems consume LLM output without sufficient validation, enabling injection attacks (XSS, SSRF, code execution).
 Not Detected
Requires application-level output inspection; not observable in network logs.
LLM06:2025
Excessive Agency
LLM-based agents are granted too many permissions, actions, or autonomy — enabling unintended or harmful automated actions.
 Partial
Agentic AI tools (e.g., autonomous code execution platforms) are flagged as Critical risk in the inventory.
LLM07:2025
System Prompt Leakage
Confidential system prompt contents — including instructions, personas, or business logic — are exposed to end users.
 Not Detected
Requires application-layer inspection of request/response payloads.
LLM08:2025
Vector and Embedding Weaknesses
Attacks against retrieval-augmented generation (RAG) pipelines — including poisoned vector stores, embedding inversion, or cross-tenant data leakage.
 Partial
RAG/vector DB tools (Pinecone, Weaviate, Chroma) are detected and inventoried; attack patterns are not.
LLM09:2025
Misinformation
LLMs generate plausible but false information (hallucinations) that is then acted upon by users or downstream systems.
 Not Detected
Output accuracy requires semantic evaluation — outside the scope of network log analysis.
LLM10:2025
Unbounded Consumption
Unrestricted resource consumption by LLM workloads — leading to denial of service, excessive cost, or degraded availability.
 Yes
High-frequency call patterns to LLM APIs are surfaced via log volume analysis; anomalous usage is flagged.

The OWASP LLM Top 10 is a living document updated by the community. Check the official project page for the latest version and changelog. New entries and re-rankings are released periodically as the threat landscape evolves.
Risk Reference
Compass Risk Classification

Each AI tool detected in the log analysis is assigned a risk tier based on three factors: data exposure potential, external connectivity, and the type of AI capability the tool provides.

Critical
Direct data exfiltration risk or autonomous action capability. These tools send or process sensitive organizational data with minimal controls or oversight.
Examples: LLM APIs with file upload, agentic platforms, unsanctioned AI data pipelines
High
Significant data sharing with external AI providers, or tools likely to be used with confidential business content without explicit policy coverage.
Examples: AI writing assistants, code completion tools, document summarizers
Medium
Moderate risk — AI-assisted features that process user input externally but have limited data persistence or established vendor data handling agreements.
Examples: AI search enhancement, sentiment analysis tools, grammar assistants
Low
Minimal risk — AI features operating locally, with anonymous inputs, or with established enterprise data processing agreements and access controls.
Examples: On-device spell check, approved enterprise AI add-ins with DPA
